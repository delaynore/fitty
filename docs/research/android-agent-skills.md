# Android agent skills for Fitty

Start with `compose-state-and-effects` and `compose-ui-testing-patterns` on the next change to workout entry. Use `compose-focus-navigation` if that change affects focus. Add `kotlin-concurrency-and-flow` when a task changes how a ViewModel observes Room or hands an asynchronous result back to the screen. These are recommendations based on Fitty's current code and the upstream catalog at `44522c0`. ## Where to use them

- **Compose state and effects.** Review ownership when a change touches the rest timer, set entry, or navigation after saving. The workout ViewModel owns the rest deadline and restores it from `SavedStateHandle`. The header updates the display while the activity is resumed. Keep that lifecycle split when changing the timer. For a UI change that needs a focused test, render the affected controls from values and callbacks so the test can supply its own state. [Skill](https://github.com/chrisbanes/skills/blob/44522c0/skills/compose-state-and-effects/SKILL.md) · [Android state hoisting](https://developer.android.com/develop/ui/compose/state-hoisting) · [Workout screen](../../app/src/main/java/com/delaynore/fitty/ui/workout/WorkoutScreen.kt#L177) · [Workout ViewModel](../../app/src/main/java/com/delaynore/fitty/ui/workout/WorkoutViewModel.kt#L98)
- **Compose UI testing and focus.** A focused regression test can log a set and assert that the next available weight field receives focus, including when the lazy list has to scroll to it. Fitty waits for the logged row to appear, scrolls to the next row, then requests focus from that row's effect. Keep the existing full-app test for resuming and finishing a workout offline because it exercises activity relaunch and Room persistence. [Testing skill](https://github.com/chrisbanes/skills/blob/44522c0/skills/compose-ui-testing-patterns/SKILL.md) · [Focus skill](https://github.com/chrisbanes/skills/blob/44522c0/skills/compose-focus-navigation/SKILL.md) · [Focus code](../../app/src/main/java/com/delaynore/fitty/ui/workout/WorkoutScreen.kt#L280) · [Offline test](../../app/src/androidTest/java/com/delaynore/fitty/InProgressWorkoutTest.kt#L71)
- **Kotlin concurrency and Flow.** Use the skill to check which scope owns a write and what the screen should see when it resubscribes. The workout ViewModel already uses `flatMapLatest` and `stateIn` with `WhileSubscribed(5_000)`, and the screen collects with `collectAsStateWithLifecycle`. If finish navigation must survive recreation in a future change, represent completion in observable state. The skill's buffered channel example assumes the UI can lose a handoff after receiving it, a limitation Android documents for ViewModel events. ## Gradle on Windows

Evaluate `gradle-run` separately if build logs become hard to triage. It keeps full logs in a temporary workflow directory and gives the agent bounded diagnostics, failure fingerprints, and status by workflow ID. At the reviewed revision the Python script accepts `gradlew*` launcher names, uses Windows file locks, and has Windows process-tree cleanup. Its Windows process tests use mocks. On the current PowerShell PATH, `python3` resolves to a WindowsApps alias and `python3 --version` exits with status `9009`, so this review could only inspect the source. Before adopting it, verify one local run of Fitty's `gradlew.bat` with `:app:assembleDebug :app:lintDebug` through the wrapper. Use the documented dedicated emulator when evaluating the device-test command. ## When the rest of the catalog fits

- Use `compose-component-design` when a shared composable gains a new caller or needs a variable content region. `SwipeToRevealDelete` already takes a caller modifier and a content slot. Use `compose-animations` if a change adds a transition, and `compose-performance` for an observed rendering problem such as a stutter during set entry. Use `android-benchmark-comparison` when a decision needs controlled measurements of competing configurations on physical hardware. [Shared composable](../../app/src/main/java/com/delaynore/fitty/ui/SwipeToRevealDelete.kt#L35) · [Compose and benchmarking skills](https://github.com/chrisbanes/skills/tree/44522c0030ca852f8f489bbd155311b20c00b12d#benchmarking)
- Use `kotlin-control-flow` for a particular branching change and `kotlin-api-design` when a new API needs a clear owner or domain type. Keep Fitty's single Android module and repository boundaries as the starting point. Use `using-chrisbanes-skills` as an index if several of the upstream skills are in use.
