# Robolectric и AOSP ATD для Fitty

Robolectric 4.18.1 поддерживает Compose и Android API 36, но запуск на API 36 блокирует текущий JDK 17. Стабильный образ AOSP ATD для API 36 и `x86_64` доступен в Android SDK. По исходникам он подходит для проверки с `FittyTestRunner` и авиарежимом. Запуск тестов Fitty на Robolectric и на ATD в GitHub Actions ещё предстоит проверить в [спайке №51](https://github.com/delaynore/fitty/issues/51).

## Robolectric

| Проверка | Вывод |
| --- | --- |
| API 36 на текущем JDK | **Блокер.** В стабильном Robolectric 4.18.1 для Android 16 (Baklava, API 36) указан минимум Java 21. По умолчанию Robolectric выбирает API из `targetSdk`. Для спайка можно поставить JDK 21 для процесса Gradle `Test` через `javaLauncher` и оставить компиляцию на Java 17. Gradle 8.13 поддерживает обе версии. [Релиз 4.18.1](https://github.com/robolectric/robolectric/releases/tag/robolectric-4.18.1) · [Таблица SDK в исходниках](https://github.com/robolectric/robolectric/blob/robolectric-4.18.1/robolectric/src/main/java/org/robolectric/plugins/DefaultSdkProvider.java) · [Выбор API](https://robolectric.org/configuring/#configure-sdk-level) · [Gradle 8.13](https://docs.gradle.org/8.13/userguide/compatibility.html#java) · [Настройка Java для Test](https://docs.gradle.org/8.13/userguide/toolchains.html#toolchains_for_tasks) |
| Запуск на JDK 17 | **Ограничение.** Можно явно указать `@Config(sdk = [35])`. Приложение по-прежнему собирается с `compileSdk = 36` и декларирует `targetSdk = 36`, а тест получает Android 15 и не проверяет поведение платформы Android 16. [Таблица SDK](https://github.com/robolectric/robolectric/blob/robolectric-4.18.1/robolectric/src/main/java/org/robolectric/plugins/DefaultSdkProvider.java) · [Выбор API](https://robolectric.org/configuring/#configure-sdk-level) |
| `createComposeRule` | **Работает по документации.** Android поддерживает локальные Compose UI-тесты с Robolectric. В Fitty `createComposeRule` уже используют `SetFieldsCursorTest` и `TrainingDayEditorContentTest`. Для локального прогона нужны Robolectric, AndroidX Test JUnit и Compose BOM с `ui-test-junit4` в `testImplementation`, а также `testOptions.unitTests.isIncludeAndroidResources = true`. Тестовую Activity даёт `ui-test-manifest` в `debugImplementation`. В тесте можно использовать `AndroidJUnit4`. Robolectric документирует флаги `--add-opens` для JDK 17 и выше. В спайке стоит проверить действия с курсором и фокусом на точных версиях Fitty. [Документация Android](https://developer.android.com/training/testing/local-tests/robolectric#ui-testing) · [Настройка Compose](https://developer.android.com/develop/ui/compose/testing#setup) · [Настройка Robolectric](https://robolectric.org/getting-started/#running-with-java-17-and-higher) · [Тест курсора](../../app/src/androidTest/java/com/delaynore/fitty/SetFieldsCursorTest.kt) · [Тест редактора дня](../../app/src/androidTest/java/com/delaynore/fitty/TrainingDayEditorContentTest.kt) |
| `Context` и `PackageManager` | **Работает по исходникам для обычных запросов к пакету.** Robolectric поддерживает `ApplicationProvider.getApplicationContext()` и подменяет `getPackageInfo`. Для тестов обновления остаётся **ограничение**. Robolectric подменяет разрешение на установку и может подменить метаданные архива. Проверку, которая читает версию из APK через `getPackageArchiveInfo`, нужно прогнать с текущим тестовым APK. Взаимодействие с системным установщиком требует устройства или эмулятора. [Поддержка AndroidX Test](https://robolectric.org/androidx_test/) · [ShadowApplicationPackageManager](https://github.com/robolectric/robolectric/blob/robolectric-4.18.1/shadows/framework/src/main/java/org/robolectric/shadows/ShadowApplicationPackageManager.java) · [ShadowPackageManager](https://github.com/robolectric/robolectric/blob/robolectric-4.18.1/shadows/framework/src/main/java/org/robolectric/shadows/ShadowPackageManager.java) · [Тесты обновления](../../app/src/androidTest/java/com/delaynore/fitty/GitHubUpdateServiceTest.kt) · [Проверка архива](../../app/src/main/java/com/delaynore/fitty/data/updates/UpdateApkCache.kt) |
| Room и тестовое приложение | **Ограничение.** Robolectric по умолчанию использует нативную реализацию SQLite. Простые тесты Compose и `GitHubUpdateServiceTest` можно проверять отдельно от Room. Если JVM-тесту нужно тестовое приложение с отдельной базой, его задаёт `@Config(application = …)` с классом, доступным из `src/test`. `FittyTestRunner` создаёт и чистит тестовое приложение в инструментальном прогоне, поэтому тесты с Room и этим жизненным циклом требуют отдельной проверки перед переносом. [SQLite в Robolectric](https://robolectric.org/upgrade_to_version_4/#migrating-to-417) · [Класс Application](https://robolectric.org/configuring/#configure-application-class) · [FittyApplication](../../app/src/main/java/com/delaynore/fitty/FittyApplication.kt) · [FittyTestRunner](../../app/src/androidTest/java/com/delaynore/fitty/FittyTestRunner.kt) |

## AOSP ATD в GitHub Actions

| Проверка | Вывод |
| --- | --- |
| Образ для текущего API | **Работает по каталогу.** Google публикует `system-images;android-36;aosp_atd;x86_64`, ревизию 1, канал stable. Пакет требует Android Emulator 35.4.9 или новее. Проверил запись в XML и ответ HTTP 200 от архива. Проверенный снимок `android-emulator-runner@v2` (`a421e43`) передаёт sdkmanager именно этот идентификатор при `api-level: 36`, `target: aosp_atd`, `arch: x86_64`. Текущий CI уже включает KVM на `ubuntu-24.04`. [Каталог Google](https://dl.google.com/android/repository/sys-img/aosp_atd/sys-img2-3.xml) · [Архив API 36](https://dl.google.com/android/repository/sys-img/aosp_atd/x86_64-36_r01.zip) · [Установка образа](https://github.com/ReactiveCircus/android-emulator-runner/blob/a421e43855164a8197daf9d8d40fe71c6996bb0d/src/sdk-installer.ts) · [CI](../../.github/workflows/android.yml) |
| Анимации и кэш AVD | **Работает по инструкции экшена.** `disable-animations: true` уже задано по умолчанию в проверенной версии. Экшен после загрузки выставляет три системных масштаба анимации в ноль. Для кэша документация предлагает сохранить чистый снимок AVD через `actions/cache`, повторно использовать AVD с `force-avd-creation: false` и запускать тесты с `-no-snapshot-save`. Ключ кэша должен различать API, образ, ABI и версию эмулятора. Так старый снимок `google_apis` или снимок от другого эмулятора не попадёт в прогон ATD. [Параметры экшена](https://github.com/ReactiveCircus/android-emulator-runner/blob/a421e43855164a8197daf9d8d40fe71c6996bb0d/action.yml) · [Отключение анимаций](https://github.com/ReactiveCircus/android-emulator-runner/blob/a421e43855164a8197daf9d8d40fe71c6996bb0d/src/emulator-manager.ts) · [Пример кэша AVD](https://github.com/ReactiveCircus/android-emulator-runner/blob/a421e43855164a8197daf9d8d40fe71c6996bb0d/README.md#avd-caching) |
| Gradle Configuration Cache | **Ограничение.** `org.gradle.configuration-cache=true` включает кэш конфигурации Gradle независимо от кэша AVD. В Fitty свойство пока отсутствует. Чтобы подтвердить совместимость задач Fitty, нужны два вызова `:app:connectedDebugAndroidTest` с одинаковыми параметрами и сообщение о повторном использовании записи на втором вызове. Для переноса записи между запусками CI через `setup-gradle@v6` нужен `cache-encryption-key`. [Свойства Fitty](../../gradle.properties) · [Gradle 8.13](https://docs.gradle.org/8.13/userguide/configuration_cache.html#config_cache:usage:enable) · [Кэш setup-gradle](https://github.com/gradle/actions/blob/v6/docs/setup-gradle.md#cache-encryption-key) |
| `FittyTestRunner` и Room | **Работает по контракту инструментации.** `:app:connectedDebugAndroidTest` запускает указанный в конфиге `AndroidJUnitRunner`. Подкласс Fitty подставляет свой `Application` и удаляет базу при завершении. Тестовое приложение открывает Room с отдельным именем файла. Этот код использует Android и AndroidX. По конфигу и исходникам зависимости от Google Play Services у раннера нет. ATD убирает предустановленные приложения, часть фоновых служб и аппаратный рендеринг. Тесты, которые открывают системный интерфейс или зависят от рендеринга, требуют проверки на выбранном образе. [Runner в конфиге](../../app/build.gradle.kts) · [FittyTestRunner](../../app/src/androidTest/java/com/delaynore/fitty/FittyTestRunner.kt) · [Ограничения ATD](https://developer.android.com/studio/test/managed-devices#use-atd) |
| Авиарежим | **Ограничение.** Совместимость ожидается по исходникам Android 16. Fitty запускает `cmd connectivity airplane-mode enable/disable` через `UiAutomation.executeShellCommand`. AOSP ConnectivityService принимает эти команды, меняет `Settings.Global.AIRPLANE_MODE_ON` и рассылает событие. У AOSP Shell есть `NETWORK_SETTINGS`, одно из разрешений, которое принимает служба. Каталог SDK подтверждает доступность образа. Проверку службы и разрешений в загруженном ATD даёт прогон офлайн-теста Fitty, который читает `airplane_mode_on` и восстанавливает исходный режим. [Офлайн-тест](../../app/src/androidTest/java/com/delaynore/fitty/InProgressWorkoutTest.kt#L125) · [UiAutomation](https://developer.android.com/reference/android/app/UiAutomation#executeShellCommand(java.lang.String)) · [ConnectivityService Android 16](https://android.googlesource.com/platform/packages/modules/Connectivity/+/refs/tags/android-16.0.0_r1/service/src/com/android/server/ConnectivityService.java) · [Манифест Shell Android 16](https://android.googlesource.com/platform/frameworks/base/+/refs/tags/android-16.0.0_r1/packages/Shell/AndroidManifest.xml) |

В [№51](https://github.com/delaynore/fitty/issues/51) первым кандидатом на JVM будет `SetFieldsCursorTest` с Robolectric 4.18.1, API 36 и JDK 21. Для AOSP ATD подойдёт офлайн-тест из `InProgressWorkoutTest`. Он за один запуск проверяет Compose, базу тестового приложения и переключение авиарежима. Повторный запуск покажет, загрузился ли снимок AVD и переиспользовал ли Gradle конфигурацию.
